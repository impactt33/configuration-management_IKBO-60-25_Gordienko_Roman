# Эмулятор командной оболочки UNIX

Практическая работа №1 по дисциплине «Конфигурационное управление»,
вариант 7.

## Общее описание

Эмулятор командной строки UNIX-подобной ОС с графическим интерфейсом
на tkinter. Пользователь вводит команды в окне, эмулятор разбирает их
и печатает результат, как обычный терминал. Эмулятор настраивается
параметрами командной строки, загружает VFS из XML в память, ведёт
XML-лог вызовов команд и умеет выполнять стартовый скрипт.

Работа выполняется по этапам:

| Этап | Содержание | Статус |
|---|---|---|
| 1. REPL | окно, парсер, заглушки `ls` и `cd`, команда `exit` | готов |
| 2. Конфигурация | параметры командной строки, XML-лог, стартовый скрипт | готов |
| 3. VFS | виртуальная файловая система из XML-файла | готов |
| 4. Основные команды | `ls`, `cd`, `du`, `pwd`, `tree` | — |
| 5. Дополнительные команды | `rmdir`, `chmod` | — |

## Функции и настройки

### Параметры командной строки

| Параметр | Описание |
|---|---|
| `--vfs PATH` | путь к XML-файлу VFS. Файл загружается в память; имя без расширения показывается в заголовке |
| `--log PATH` | путь к XML-логу вызовов команд. Без параметра лог не ведётся |
| `--script PATH` | путь к стартовому скрипту, который выполняется сразу после запуска |
| `-h`, `--help` | справка по параметрам |

Все параметры необязательные. Относительные пути считаются от папки,
из которой запущен эмулятор.

При запуске эмулятор печатает в окно значения всех параметров
(отладочный вывод), незаданные равны `None`:

```
vfs: vfs/minimal.xml
log: logs/session.xml
script: None
```

Неизвестный параметр или параметр без значения дают ошибку, и окно не
открывается:

```
main.py: error: unrecognized arguments: --lgo logs/x.xml
main.py: error: argument --log: expected one argument
```

### Окно

- Заголовок: `Shell emulator - VFS: <имя>`. Имя берётся из `--vfs`, без
  параметра показывается `vfs not specified`.
- Приглашение имеет вид `пользователь@хост:~$`.
- Введённая команда и её результат добавляются в поле вывода.
  Редактировать поле вывода нельзя.

### Команды

| Команда | Описание |
|---|---|
| `ls [аргументы]` | заглушка: выводит имя команды и список аргументов |
| `cd [аргументы]` | заглушка: выводит имя команды и список аргументов |
| `exit` | закрывает окно эмулятора, с аргументами выдаёт ошибку |

### Виртуальная файловая система

При запуске с `--vfs` эмулятор читает XML-файл и создаёт дерево папок и
файлов в памяти. Исходный XML не изменяется, данные не извлекаются на диск.
Корень задаётся элементом `<directory name="/">` внутри `<vfs>`.
Вложенные папки задаются элементами `<directory name="...">`, а файлы —
элементами `<file name="..." encoding="...">`.

Для текстовых файлов содержимое элемента хранится строкой. При
`encoding="base64" оно декодируется в байты. Например:

```xml
<vfs>
  <directory name="/">
    <file name="readme.txt" encoding="utf-8">Hello</file>
    <file name="data.bin" encoding="base64">AAECA//+</file>
  </directory>
</vfs>
```

В `vfs/` находятся три примера: `minimal.xml` с пустым корнем,
`several_files.xml` с текстовыми и двоичным файлами и `deep.xml` с
папками глубиной более трёх уровней. На этом этапе `ls` и `cd` остаются
заглушками; работу с деревом будут выполнять команды следующего этапа.

### Разбор командной строки

- Аргументы разделяются пробелами и табуляцией, лишние пробелы
  пропускаются.
- Двойные `"..."` и одинарные `'...'` кавычки объединяют слова в один
  аргумент: `cd "My Documents"` передаёт один аргумент `My Documents`.
- Пробелы внутри кавычек сохраняются как есть.
- Кавычка другого вида внутри кавычек считается обычным символом:
  `"it's"`.
- Кавычки не разрывают слово: `"a b"c` даёт один аргумент `a bc`.
- Всё после `#` вне кавычек считается комментарием и отбрасывается.
  `#` внутри кавычек остаётся обычным символом.

### Стартовый скрипт

Текстовый файл с командами эмулятора, по одной на строку.

- Комментарии записываются через `#`, как в Python: на отдельной
  строке или в конце строки с командой.
- Пустые строки пропускаются.
- Каждая строка печатается в окне вместе с приглашением, а под ней
  результат, как будто команды вводит пользователь.
- На первой ошибке выполнение останавливается с номером строки. Дальше
  эмулятор работает в обычном режиме.
- Команда `exit` в скрипте закрывает эмулятор.

Пример (`scripts/no_errors.txt`):

```
# Без кавычек: два отдельных аргумента
cd 123 123
# В кавычках: один аргумент с пробелом
cd "123 123"
ls -l 12 4 dv  # комментарий в конце строки отбрасывается
```

### XML-лог

Каждый вызов команды записывается в лог событием `<event>` с датой и
временем, именем пользователя, именем команды и аргументами:

```xml
<?xml version='1.0' encoding='utf-8'?>
<log>
  <event>
    <datetime>2026-10-28T17:38:45</datetime>
    <user>impact</user>
    <command>cd</command>
    <args>
      <arg>123 123</arg>
    </args>
  </event>
  <event>
    <datetime>2026-10-28T17:38:45</datetime>
    <user>impact</user>
    <command>ls</command>
    <args />
  </event>
</log>
```

- Записываются команды из окна и из стартового скрипта, включая
  неизвестные команды и `exit`.
- Пустые строки, комментарии и строки с ошибкой разбора не
  записываются.
- Файл создаётся при первом событии, папка для него создаётся
  автоматически.
- Если файл уже существует, новые события дописываются к старым.
- Файл перезаписывается целиком после каждого события, поэтому всегда
  остаётся корректным XML.

### Обработка ошибок

| Ситуация | Сообщение |
|---|---|
| неизвестная команда | `<имя>: unknown command.` |
| незакрытая кавычка | `Unclosed quote: "` |
| `exit` с аргументами | `exit: too many arguments.` |
| ошибка в стартовом скрипте | текст ошибки и `Script error at line N, execution stopped.` |
| стартовый скрипт не читается | `Script error: cannot read <путь>` |
| лог-файл повреждён или недоступен | `Log error: cannot use <путь>: <причина>`, эмулятор работает без лога |
| VFS не найдена или XML повреждён | `VFS error: cannot load <путь>: <причина>`, окно открывается без VFS |

Пустая строка или строка из одного комментария ничего не выводит.

### Устройство программы

```
hw1/
├── src/
│   ├── main.py         точка входа, параметры командной строки
│   ├── gui.py          окно на tkinter, стартовый скрипт
│   ├── shell.py        разбор и выполнение команд
│   ├── logger.py       XML-лог
│   ├── vfs_reader.py   загрузка VFS из XML
│   └── errors.py       исключения
├── tests/
│   ├── test_shell.py   тесты разбора, выполнения и логирования команд
│   ├── test_logger.py  тесты XML-лога
│   ├── test_main.py    тесты разбора параметров
│   └── test_vfs.py     тесты загрузки VFS
├── scripts/            стартовые скрипты и тестовые скрипты ОС
├── vfs/                три примера XML-файлов VFS
├── run.sh              запуск эмулятора
└── test.sh             запуск тестов
```

| Функция / класс | Модуль | Назначение |
|---|---|---|
| `parse_args(argv)` | `main.py` | разбирает параметры командной строки |
| `parse_command(command)` | `shell.py` | разбивает строку на имя команды и аргументы |
| `execute(line, logger)` | `shell.py` | выполняет строку и возвращает текст для вывода, пишет вызов в лог |
| `cmd_ls`, `cmd_cd`, `cmd_exit` | `shell.py` | реализация команд, словарь `COMMANDS` связывает их с именами |
| `XmlLogger` | `logger.py` | XML-лог: метод `log(command, arguments)` добавляет событие |
| `ShellWindow` | `gui.py` | окно: `run_line` выполняет введённую строку, `run_script` выполняет стартовый скрипт |
| `ShellError` | `errors.py` | общий родитель ошибок, о которых сообщается пользователю |
| `ParseError`, `UnclosedQuote` | `errors.py` | ошибки разбора командной строки |
| `CommandError`, `UnknownCommand`, `TooManyArguments` | `errors.py` | ошибки выполнения команд |
| `ExitRequest` | `errors.py` | сигнал, которым `exit` просит закрыть окно |
| `VFS`, `Directory`, `File` | `vfs_reader.py` | дерево VFS, папка и файл в памяти |
| `get_vfs(path)` | `vfs_reader.py` | загружает XML-файл в VFS |
| `read_directory(element)` | `vfs_reader.py` | рекурсивно загружает вложенные папки и файлы |
| `VfsNotFound`, `InvalidVfs` | `errors.py` | ошибки отсутствующего файла и корневой папки VFS |

Логика команд не зависит от tkinter, а логгер передаётся в `execute`
снаружи. Поэтому команды тестируются без окна и без записи файлов.

## Сборка, запуск и тесты

Требования: Python 3.10 или новее и tkinter. В Ubuntu/Debian tkinter
ставится пакетом `python3-tk`, в Arch Linux пакетом `tk`. Сторонние
библиотеки не нужны, сборка не требуется.

```bash
./run.sh                                  # запуск без параметров
./run.sh --vfs vfs/minimal.xml --log logs/session.xml \
    --script scripts/no_errors.txt        # запуск со всеми параметрами
./test.sh                                 # модульные тесты
./scripts/test_vfs.sh                     # минимальная VFS и ошибки загрузки
./scripts/test_vfs_files.sh               # VFS с несколькими файлами
./scripts/test_vfs_deep.sh                # VFS с вложенными папками
```

Модульные тесты написаны на `unittest`. Без скрипта их можно запустить
так (из папки `hw1`):

```bash
PYTHONPATH=src python3 -m unittest discover -s tests -v
```

### Тестовые скрипты ОС

Скрипты в `scripts/` запускают эмулятор с разными параметрами. Каждый
вызов открывает окно, следующий начинается после его закрытия. Перед
каждым вызовом скрипт пишет в терминал, что проверяется.

| Скрипт | Что проверяет |
|---|---|
| `scripts/test_args.sh` | `--help`, неизвестный параметр, параметр без значения, запуск без параметров |
| `scripts/test_vfs.sh` | минимальная VFS, отсутствующий файл и неверный XML |
| `scripts/test_vfs_files.sh` | VFS с несколькими файлами и base64 |
| `scripts/test_vfs_deep.sh` | VFS с вложенными папками |
| `scripts/test_script.sh` | стартовые скрипты: без ошибок, с ошибкой, с `exit`, несуществующий файл |
| `scripts/test_log.sh` | новый лог, дописывание в существующий, повреждённый файл |
| `scripts/test_all.sh` | все параметры вместе |

Стартовые скрипты эмулятора для них: `scripts/no_errors.txt`,
`scripts/with_errors.txt`, `scripts/with_exit.txt` и
`scripts/stage3_demo.txt`. Последний показывает команды и ошибку `exit 1`
после загрузки VFS. Логи складываются в `logs/`, эта папка не попадает в
репозиторий.

## Примеры использования

Сеанс работы в окне эмулятора:

```
user@host:~$ ls -l /home
ls: ['-l', '/home']
user@host:~$ cd "My Documents"
cd: ['My Documents']
user@host:~$ cd 'it is' "it's"
cd: ['it is', "it's"]
user@host:~$ cd "a b"c
cd: ['a bc']
user@host:~$ ls /etc  # comment
ls: ['/etc']
user@host:~$ pwd
pwd: unknown command.
user@host:~$ cd "unclosed
Unclosed quote: "
user@host:~$ exit 1
exit: too many arguments.
user@host:~$ exit
```

После `exit` окно закрывается.

Стартовый скрипт с ошибкой, `./run.sh --script scripts/with_errors.txt`:

```
vfs: None
log: None
script: scripts/with_errors.txt
user@host:~$ # Стартовый скрипт с ошибкой: выполнение остановится на неизвестной команде.
user@host:~$ cd 123 123
cd: ['123', '123']
user@host:~$ cd "123 123"
cd: ['123 123']
user@host:~$ ls -l 12 4 dv
ls: ['-l', '12', '4', 'dv']
user@host:~$ # Неизвестная команда: здесь скрипт остановится
user@host:~$ cf
cf: unknown command.
Script error at line 7, execution stopped.
```

Повреждённый лог, `./run.sh --log logs/broken.xml`:

```
vfs: None
log: logs/broken.xml
script: None
Log error: cannot use logs/broken.xml: no element found: line 1, column 12
```
